# error-attribution 使用说明

## 这个 Skill 是做什么的

把你做错的题拆开看，判断错在哪一类，并给出能照着做的改进策略。四类归因是：

1. 概念不清：定义、定理或概念理解有偏差。典型表现是混淆相似概念、记错定义条件、不清楚适用范围。
2. 方法缺失：这类题的解法不会或不熟。典型表现是不知道从何下手、不知道用什么工具、步骤不完整。
3. 思维盲区：方法和概念都会，但当时没联想到。典型表现是忽略隐含条件、漏看关键线索、方向对了中途走偏。
4. 计算失误：思路方法都对，只是算错推错。典型表现是符号错、代数错、代入错、跳步漏项。

可以多选，但一定会指出主要原因是哪一类。

## 怎么触发

在学习场景里说这些话即可：错题、归因、分析错误、我错了、这题怎么做错了。

最好把题目和你自己的答案一起给它，有解题过程更好——过程越全，归因越准。

## 触发后会发生什么

1. 复述题目、你的答案和你的思路。你只给了答案没给过程时，它会先问你怎么算的；实在问不到就说清哪些结论是从答案反推的。
2. 判定错误类型，每条判断依据都会指到你答案里的具体位置（哪一步、哪个式子）。
3. 定位环节，明确说"你在哪一步走偏了"。
4. 按类别给策略：概念不清就指出要重学的知识点；方法缺失就补方法加例题；思维盲区就给下次的检查清单；计算失误就给验算和书写建议。
5. 同一类错误反复出现，或你说"又错了"，会标记为"重点薄弱环节"并给专项训练方案。

## 这些情况它不会启动

1. 日常认错道歉，比如"我错了，下次注意"。
2. 与解题无关的错误，比如文档写错字。
3. 要讲解知识点、出练习题、整理复习材料——那是另外三个 Skill 的活。

## 输出样式

归因结论、主要错误类型和判断依据里引用的痕迹可以用粗体、斜体、高亮、颜色和少量 emoji 突出，方便一眼看到重点。为了保证在 Markdown、PDF、Word 里都能正常显示，只使用各载体都支持的写法：优先用粗体，颜色不单独承载信息（旁边必有文字或粗体），emoji 每段最多一两个且只用常见基础款，不使用特殊字体符号和组合型 emoji，防止乱码或显示成方框。

## 修改与验证

想调整行为，改 SKILL.md 里的规则即可。改完可用 evals\evals.json 复测，重点看三条：认错道歉是否不触发；判计算失误前是否先查过有没有隐藏的概念或方法问题；归因是否真的指到了答案里的具体位置，而不是空话。
